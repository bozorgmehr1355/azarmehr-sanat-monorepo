# TANKHAHYAR_ADMIN_PANEL_LAYOUT.md
# Admin Panel Layout Specification — تنخواه‌یار (TankhahYar)

**نسخه سند:** 1.0  
**وضعیت:** تایید شده  
**آخرین بروزرسانی:** ۲۰۲۶-۰۷-۲۵  
**مخاطبان:** توسعه‌دهندگان، مربی UI/UX، مدل‌کنندگان

---

## ۱. مقدمه

این سند **مخطط صفحه مدیریت تنخواه‌یار** را به صورت جزئی تعریف می‌کند تا تیم‌های توسعه و طراحی محصول برای ساخت یک پنل با راه‌یابی، ارائه و قابلیت‌های دسترسی‌ی هدف‌مند، به صورت هماهنگ عمل کنند. این سند تنظیم‌های کلیدی RTL، شرط‌های واکنش‌پذیر صفحه، صفحات ادمین اصلی و ساختار کلی حل‌شونده را تشریح می‌کند.

> مبنای استخراج: الگو‌های سفارشی که همجنین مقاله طراحی محصول دارد.

### ۲.۲ ملاحظات RTL

| جنبه | اعمال |
|--------|--------|
| **ریشه HTML** | `dir=\"rtl\"` |
| **به‌صورت پیش‌فرض، ویرایش** | از `margin-right` به جای `margin-left` استفاده کنید |
| **آیکون‌ها** | برای آیکون‌های جهت‌داده از `fa fa-angle-left` برای اقدامات `>`, `fa fa-angle-right` برای اقدامات `<` استفاده کنید. |
| **رنگ‌های محتوا** | متن در سمت راست: `text-right` |
| **انتقال** | `transform: translateX(0)` برای RTL |
| **بند** | `rounded-lg` با `border-radius: ۰.۵rem` (ساخته شده برای استقرار در RTL) |

## ۳. سایدبار (دسکتاپ > ۹۰۰px)

### ۳.۱ ساختار سایدبار اصلی

- **سطح ۱:** مجموعه‌های اصلی:
  1. **داشبورد** (`/`) - داشبورد جهانی، تمامی KPIها.
  2. **صندوق‌ها** (`/funds`) - لیست صندوق‌ها، اقدامات کریک، جستجو.
  3. **هزینه‌ها** (`/expenses`) - لیست، فیلتر، جستجو.
  4. **تأییدها** (`/approvals`) - صفحه انتظار تأیید.
  5. **تسویه‌ها** (`/settlements`) - لیست تسویه‌ها، پرداخت‌ها.
  6. **خروجی‌های حسابداری** (`/accounting-exports`) - صادرات مهاد.
  7. **کاربرها و نقش‌ها** (`/users`) - مدیریت کاربران، نقش‌ها، دسترسی‌ها.
  8. **سیاست‌ها** (`/settings`) - تنظیمات جهانی.
  9. **لاگ ممیز** (`/audit-log`) - گزارش‌گیری ممیز.

- **سطح ۲:** در صورتی که وجود داشته باشد (مثلاً زیر مجموعه صندوق):
  1. **جزئیات صندوق** (`/funds/:id`) - مانده, هزینه‌ها, شارژ/تسویه.
  2. **جزئیات هزینه‌ها** (`/expenses/:id`) - خلاصه وضعیت, روند تأیید.

### ۳.۲ طراحی واکنش‌پذیر سایدبار (smartphone)

- **Drawing پاینه (≤ ۹۰۰px)**: سایدبار از حالت باز می‌شود (Drawer) از سمت راست (`right: 0`).
- **موقعیت Drawer**:
  - اسکن **mobile**: پراکندگی در سمت راست (`right: 0`, `left: -۳۲۰px`, `transform: translateX(-۱۰۰%)`).
  - **tablet**: پراکندگی در سمت راست (`right: ۰px`).
- **دکمه Toby:** `☰` → باز/بسته شدن Drawer.
- **بستن در هنگام:** روی پس‌زمینه یا دکمه بستن (`×`) کلیک کنید.
- **رویچین کلی UI:** سایدبار لایه‌ای بالاتر (`z-index: 1000`) قرار می‌گیرد.

## ۴. محتوای اصلی (Main Content)

### ۴.۱ پنجره خارجی (Outlet)

- **راست‌نویسی:** راس‌های روت معتبر آدرس مسیر web به صورت خودکار به پنجره خارجی منتقل می‌شوند.
- **رقابت:** خطوط به صورت آنی با `React Router` آپدیت می‌شوند.

### ۴.۲ نوار اقدام‌های زمینه‌ای

هر صفحه یک نوار اقدام‌های زمینه‌ای قابل مشاهده دارد که شامل موارد زیر است:

| عنصر | مثال | موقعیت |
|---------|---------|-------------|
| **ویرایش** | `Create Fund` / `Edit Expense` | در سمت راست؛ قابل مشاهده از کل صفحه |
| **Batch Actions** | `Select multiple` + `Actions` (تأیید/رد با هم) | برای صفحات لیست قابل مشاهده |
| **جستجو/فیلتر** | `Search expenses...` | در بالای لیست قابل مشاهده |
| **گزینه‌های نمایش** | `Visible columns: ID, Amount, Status` | به صورت پاپ‌آپ دکمه دار |
| **Enteries** | `Export PDF / Export Excel` | برای عملیات مددا قابل مشاهده |

## ۶. تجربه کاربر (User Experience) به صورت اولیه

### ۶.۱ خط مستحکم (Figma / Adobe XD)

- **نگهداشت‌های UI:** Figma Community Plan (اشتراک تیم برای دسترسی).
- **مبانی‌ها:** تصاویر اسکرین، آنیمیشن‌های هنگام انتقال (ترکیب).

### ۶.۲ Error Pages

- **۴۰۴:** “صفحه‌ای مورد نظر یافت نشد.” (با یک دکمه برای بازگشت به داشبورد).
- **۵۰۰:** “خطای سرور. لطفا بعداً دوباره تلاش کنید.”
- **۴۰۳:** “دسترسی ممنوع.” (با یک دکمه برای اتمام کار).

### ۶.۳ Loading States

- **اسکلتون:** نوع قابل اتکای برای همه آنها، بر اساس سبک صفحات.
- **Loaders دیگر:** spinner مرکزی، progress bar برای عملیات طولانی (مثلاً: بک‌گراند بارگذاری فایل‌های بزرگ).

### ۶.۴ پیام‌های موفقیت/هشدار

- **toast‌ها:** در گوشه سمت راست، قابل انتخاب (نجاحت، هشدار، خطا).
- **toastهای پاپ‌آپ:** در صورت کار با data-attributes (مثلاً برای فرم‌های Modal).

### ۶.۵ اسکرولینگ

- **behavior:** smooth scroll (native CSS).
- **طولی:** شاید بیش از ۳۲۰px برای scroll قابل دسترس (اسکرول داخلی).

## ۷. معیار پذیرش (Acceptance Criteria)

| معیار | پاسخودادن به اعتبار |
|----------|----------------|
| ✅ **RTL Lens** | تمام UI ظاهر به صورت خودکار RTL است (ریشه، align-center, margin-left). |

| ✅ **قابلیت دسترسی** | ARIA به صورت خودکار استفاده می‌شود (label‌ها، status updates). |

## ۹. ملاحظات برای توسعه (Implementation Notes)

### ۹.۱ فریم‌ورک React

- **پکیج:** `Create React App`، `CRA` + TypeScript.
- **مجموعه:** ``src/`` → `components/`, `pages/`, `features/`, `hooks/`, `utils/`, `services/`.
- **استقرار:** `public/index.html` → لایه‌های اسناد‌آرای.
- **محرک:** **React Router** برای مسیرهای نگهداشت‌شده.
- **همگام‌سازی:** **Redux Toolkit + RTK Query** (گزینه مسئولیت و عملیات) یا **Zustand** (ساده‌تر, برای کوچک).
- **QWidget:** **Material-UI (MUI)** یا **Ant Design** (ماکز از وجود ندارد؟) – از آن‌ها برای سفارش اجزای UI path استفاده کنید.

### ۹.۲ تعهد دوم (Ant Design)

- **تعماد:** وارد `ant.design` شوید.
- **خوب:** رابطه‌های اولیه (`Button, Card, Table, Modal, Drawer, Select, Input`) آماده هستند.
- **UI:** استایل‌شده برای اعتاد به**LTS** به صورت خودکار.

### ۹.۳ API / Remote integration

- **baseURL:** از env (باید به صورت محیطی از Service Worker بارگذاری شود).
- **مختصر:** `fetch` / `axios`.
- **سررسپسون:** درصورت کار با استقرار زیرد، ناحیه‌های کیف پول،ید.
- **قابلیت‌های مجاز برای Utter**: JWT مرور علیه protected endpoints.

### ۹.۴ امانی برای شرکتها

- **اجازه به شخصیت** (`PermissionMiddleware`) → بررسی اقدامات API بر اساس User Roles + Tenant isolation.
