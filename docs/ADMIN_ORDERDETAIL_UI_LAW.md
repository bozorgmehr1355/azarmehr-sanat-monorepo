# ADMIN_ORDERDETAIL_UI_LAW

Source of truth برای UI صفحه OrderDetail (پنل ادمین) و الگوی اپ/مسیر مشتری عمده.

مرتبط:
- ناوبری: docs/ADMIN_NAVIGATION_LAW.md (در صورت وجود)
- مرز ماژول: docs/SYSTEM_DESIGN_BASELINE.md (در صورت وجود)

این سند جایگزین baseline معماری نیست؛ فقط قانون UI است.

## هدف

- ساده (کم‌تصمیم، کم‌فیلد)
- خوانا (درشت منطقی، نه اغراق)
- منظم (کارت هم‌اندازه، قرینه، یک الگو)
- یک‌خطی (نام مشتری/کالا/برچسب/خلاصه آدرس نشکند)

PASS UI ≠ فقط API درست  
PASS UI = رعایت L1–L10 + تأیید یک‌نگاه انسانی

## مخاطب

| سطح | کی | الزام |
|---|---|---|
| کارمند/مدیر | پنل ادمین | سرعت + نظم |
| مشتری عمده | بازاری، سن بالاتر، سواد دیجیتال پایین‌تر | سادگی؛ بدون منوی تو در تو |

اندازه: یک پله خواناتر از UI شلوغ؛ دکمه لمس‌پذیر حدود 40–44px؛ نه فونت/دکمه بیلبوردی.

## قوانین سخت (L)

| کد | قانون |
|---|---|
| L1 | هر نام محصول، نام مشتری، برچسب دکمه، خلاصه آدرس = فقط یک خط (overflow ellipsis + title کامل) |
| L2 | خروجی مبهم ممنوع؛ هر عدد یک برچسب ثابت فارسی |
| L3 | کارت‌های هم‌ردیف: عرض/ارتفاع یکسان؛ الگوی ثابت برچسب \| مقدار |
| L4 | قرینه: اکشن‌ها در یک نوار؛ نه هر گوشه یک دکمه |
| L5 | Header: حداکثر ۳ اکشن اصلی؛ خطرناک (لغو) داخل «بیشتر» |
| L6 | اسکلت ثابت: Header → Primary → Secondary (جمع‌شو) |
| L7 | Primary همیشه باز: مشتری + مالی (مبلغ کل، پرداخت‌شده، مانده) + اقلام یک‌ردیفی |
| L8 | Secondary پیش‌فرض بسته: ارسال \| اسناد \| سیستم |
| L9 | اندازه = درشت منطقی (~1–1.25rem سلسله‌مراتب)، نه اغراق |
| L10 | یک target در هر فاز؛ deploy فقط با دستور صریح انسانی |

## اسکلت اجباری OrderDetail

HEADER: سفارش #N | وضعیت | حداکثر ۳ دکمه هم‌اندازه  
PRIMARY: [مشتری ½] [مالی ½] هم‌ارتفاع → سپس [اقلام تمام‌عرض]  
SECONDARY: آکاردئون‌های هم‌شکل (ارسال / اسناد / سیستم)

مالی Primary فقط سه ردیف: مبلغ کل · پرداخت‌شده · مانده.

## PASS / BLOCKED

PASS: L1–L10 روی OrderDetail + تأیید انسانی یک نگاه  
BLOCKED: چندخطی اجباری در کارت | کارت نامساوی هم‌ردیف | بیش از ۳ اکشن اصلی Header | Secondary شلوغ اجباری باز | اندازه اغراق‌شده

گزارش هر کار:
target / goal / commands / result: PASS|BLOCKED / blocker / next action

## فاز UI

U0 wire + این قانون (قفل پس از تأیید انسانی)  
→ U1 Header  
→ U2 Primary  
→ U3 Secondary  

بدون تأیید انسانی هر فاز، فاز بعد شروع نشود.
